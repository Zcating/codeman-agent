## Atomic Commit Strategy

**Convention:** Conventional Commits with scope tag.

| Scope tag | When |
|---|---|
| `db` | SQL migrations |
| `backend` | Rust changes |
| `types` | TS interfaces |
| `appStore` | `app.store.ts` |
| `store` | feature stores |
| `ui` | design-system primitives |
| `internal` | internal/ business components |
| `home` | `home.tsx` |
| `routes` | route components |
| `e2e` | e2e tests |
| `tool-call-card` / `message-bubble` / `chat-view` / `workspace-card` | icon migration per file |
| `docs` | AGENTS.md / baseline report |

**Atomic commit rules:**
1. Test + impl in same file = 1 commit (when both exist)
2. Multi-file change that fails any partial state = 1 commit
3. Deletion is its own commit
4. No "WIP" / "intermediate" commits
5. Commit message references ADR-0022 consequence row when applicable

## TDD Discipline

For each TS task that adds behavior:
1. RED: Write failing test first
2. GREEN: Implement minimum to pass
3. SURFACE: Exercise real user-facing surface
4. REGRESSION: Re-run full suite

For Rust tasks: extend existing `#[tokio::test]` cases in same file.

For TDD skips (allowed): SQL migration, field addition with sanitized() invariant test, CSS tokens (visual only), icon migration (existing tests get migrated).
