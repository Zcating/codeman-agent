## Decisions

### D-A — D4 架构修正:8 个独立 leaf classes + union(废除公共基类方案)

- `AppError` 是**类型 union**,不是类(命名借由 type alias 沿用,见 `errors.ts:58-66`)。
- 8 个 `Schema.TaggedError` 各自实现一次,instance `_tag` 由 `Schema.TaggedError<T>()("Tag", {...})` 的 ctor 参数决定。
- `isAppError(u: unknown): u is AppError` 是 OR-of-`instanceof` 的运行时守卫(`errors.ts:72-80`)。
- 拒绝理由(公共基类):见 Context D4-a。Effect 3.x 修复 `Schema.TaggedError` 子类化语义前,公共基类方案不能落地。
- 后续 ADR 若 Effect 修复子类化,需新 ADR 重新审视本决策。

### D-B — D4 SandboxViolation.message 修正:PR 5 之前 optional,之后 throw site 必填

- PR 1–PR 4(含 `master@559d0c9`):`message: Schema.optional(Schema.String)`。
- "PR 5 起" = 合约生效:新 throw site 必须补 `message`(review reject 含未补 message 的新 throw site);PR 5 不直接补 8 个已知 throw site,由后续 PR 处理(见下条)。
- 字段上应加 `@deprecated` JSDoc 注释说明可选阶段过渡(本期 plan Tasks 2-12 未补,由后续 ADR 实施);过渡完毕时由后续 ADR 改为必填 `Schema.String`。
- 已知 8 个 throw site 补 `message` 由 PR 6+(后续 plan)统一处理,本次 PR 5 仅锁定 spec 文案。

### D-C — D8 helper 修正:`toToolParameters` 用 `JsonSchema.fromAST`

- helper 实现切到 `JsonSchema.fromAST(schema.ast, { definitions: {} }) as unknown as TSchema`。
- ADR-0025 D8 字面改写:`return JsonSchema.fromAST(schema.ast, { definitions: {} }) as unknown as TSchema`。
- 拒绝理由(`Schema.toJsonSchema`):3.21.x 的 `Schema.toJsonSchema` 走 `AST → JSON Schema` 转换路径,会保留 Effect 内部 annotation,导致 pi-ai AJV 对部分 keyword(`format` / `$ref`)的解析路径不同。`fromAST` 直接读 AST 输出更接近 typebox 风格,AJV 兼容性更好。

## Consequences

### 正面

- ADR-0025 与 `errors.ts` / `tool-schema.ts` 文字对齐。
- 公共基类陷阱被永久记录:以后新 `AppError` variant 走独立 leaf class 即可。
- SandboxViolation message 可选期的过渡状态有 spec 背书,review 不再反复争论。

### 负面 / 风险

- 在 Effect 官方修复 `Schema.TaggedError` 子类化语义前,新团队成员需读 ADR-0025.1 才能"看见"为什么没公共基类。
- `JsonSchema.fromAST` 是 Effect 内部 API,版本升级可能 break;需在 Effect 升级时同步回归测试。

## Migration Plan

- 本 ADR 落地为单一 doc commit:`docs(adr-0025.1): amend D4 architecture, SandboxViolation.message, D8 helper`。
- 后续 throw site 补 message 不在本 ADR scope,由 review 发现后逐 PR 处理。
- 配套变更:`src/shared/lib/tool-schema.ts` doc-comment 与 ADR D-C 文字一致(由本期 plan Task 5 处理)。
